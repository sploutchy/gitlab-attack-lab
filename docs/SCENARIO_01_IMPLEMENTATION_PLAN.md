## 1. Scenario Overview

### Learning Objectives
- Discover GitLab Personal Access Tokens (GLPAT) through CI/CD pipeline scanning
- Exploit stolen tokens to access private projects and variables
- Extract secrets from CI/CD artifacts and environment files
- Demonstrate privilege escalation via token abuse
- Understand CI/CD pipeline security risks

### Attack Flow
```
Developer (Access Level 30) 
  → Scans pipelines for exposed tokens (GLPAT)
  → Finds token with Owner (50) access level
  → Uses token to access restricted project variables
  → Dumps project variables through repo manipulation
  → Extracts secrets from artifacts (.env, build outputs)
  → Retrieves final flag
```

## 2. Technical Architecture

### Projects Involved

#### 2.1 **web-service** (Attack Starting Point)
- **Group:** root/web-service
- **Access Level:** Developer (30) can see pipelines
- **CI/CD Pipeline:** Contains exposed GLPAT
- **Purpose:** Entry point for token discovery

**Exposed Token Details:**
- GLPAT with Owner (50) access to `infrastructure-provisioner` project
- Intentionally logged in pipeline output (unmasked variable or debug mode)
- Pattern: `glpat-[A-Za-z0-9_-]{20}`

#### 2.2 **infrastructure-provisioner** (Target Project)
- **Group:** root/infrastructure-provisioner
- **Owner Access Required:** Yes (access level 50)
- **Contains Secret Variables:**
  - `DEPLOY_KEY`: SSH key for infrastructure
  - `DB_PASSWORD`: Database credentials
  - `API_SECRET`: API authentication token
  - `FLAG_LEVEL1`: First flag (discovered via token)

#### 2.3 **infrastructure-config** (Advanced Target)
- **Group:** root/infrastructure-config
- **Variables to Extract:**
  - `.env` file in artifacts containing `FLAG_LEVEL2`
  - Secrets in build artifacts
  - Environment variables dumped to CI logs

### 3.1 Web-Service Project Setup

**File:** `lab-config/ci-templates/web-service.yml`

```yaml

  - setup
  - build
  - test
  - deploy

variables:
  CI_DEBUG_TRACE: "false"
  # GLPAT exposed via unprotected variable
  PROVISIONER_TOKEN: "glpat-xyz1234567890abc"  # NOT masked, NOT protected
  
jobs:
  setup:
    stage: setup
    image: alpine:latest
    script:
      # Intentionally expose token in logs (simulate developer mistake)
      - echo "Initializing with provisioning token..."
      - echo "Token prefix: ${PROVISIONER_TOKEN:0:6}..." # Reveals enough to scan
      - echo "Full token for debugging: $PROVISIONER_TOKEN"  # <-- FLAG HERE
      - echo "Access level: Owner (50) on infrastructure-provisioner"
    artifacts:
      paths:
        - .env
      expire_in: 1 week

  build:
    stage: build
    image: ubuntu:latest
    script:
      - apt-get update && apt-get install -y curl jq
      # Job that developer could use to dump variables
      - echo "Building application..."
      - env | grep -i secret > build_secrets.txt || true
    artifacts:
      paths:
        - build_secrets.txt

  deploy:
    stage: deploy
    image: alpine:latest
    script:
      - echo "Deployment would happen here"
```

## 4. Attack Path & Flags

### Flag 1: GLPAT Token Discovery
**Flag:** `flag{cicd_glpat_leak_9f933f5d2a30}`  
**Location:** web-service pipeline logs  
**Access Required:** Developer (30) - can view own project pipelines  
**Discovery Method:**
1. Access web-service project as Developer
2. Check CI/CD → Pipelines
3. Click on "setup" job logs
4. Search for "glpat-" pattern
5. Extract full token: `glpat-xyz1234567890abc`

### Flag 2: Infrastructure-Provisioner Variables
**Flag:** `flag{cicd_glpat_leak_9f933f5d2a30}`  (Use discovered GLPAT)  
**Location:** infrastructure-provisioner project variables  
**Access Required:** Owner (50) - via stolen GLPAT  
**Discovery Method:**
1. Use pentester container with pipeleek
2. Export stolen token: `export GITLAB_TOKEN="glpat-xyz1234567890abc"`
3. Access infrastructure-provisioner variables
4. Read FLAG_LEVEL1 variable

### Flag 3: .env Artifact Extraction
**Flag:** `flag{artifact_env_leak_7d3e2c1a9b5f}`  
**Location:** infrastructure-config project artifacts  
**Access Required:** Developer (30) or via token  
**Discovery Method:**
1. Access infrastructure-config project
2. Check CI/CD → Pipelines
3. View artifacts from "setup" job
4. Download .env file
5. Extract FLAG_LEVEL2

### Flag 4: Environment Dump Extraction
**Flag:** `flag{dotenv_extracted_b2e8f1c5a3d9}`  
**Location:** env_dump.txt artifact  
**Access Required:** Developer (30) or via token  
**Discovery Method:**
1. Access infrastructure-config project

```markdown
# CI/CD Leaks - Token Discovery & Exploitation

## Objective
Learn how to discover GitLab Personal Access Tokens (GLPAT) exposed in CI/CD pipelines, use them to access restricted resources, and extract secrets from project variables and build artifacts.

## Background
CI/CD pipelines often contain sensitive information:
- Unmasked variables in logs
- Secrets in artifacts and environment files
- Access tokens with elevated privileges
- Credentials in build outputs

Developers sometimes accidentally expose these, leading to privilege escalation and data breaches.

## Scenario Steps

**Part 1: Token Discovery**
- Explore the web-service project
- Check CI/CD pipelines for exposed tokens
- Identify the GLPAT token in pipeline logs

**Part 2: Token Exploitation**
- Use the discovered token to access infrastructure-provisioner project
- Extract project variables using the token
- Retrieve secrets from the restricted project

**Part 3: Artifact Extraction**
- Access infrastructure-config project artifacts
- Download .env files from pipeline artifacts
- Extract secrets from environment dumps

**Part 4: Flag Submission**
- Submit all discovered flags
- Each flag represents a different exploitation technique

## Security Lessons
- Always mask sensitive variables in CI/CD
- Protect artifacts from unauthorized access
- Limit token access levels (principle of least privilege)
- Audit pipeline logs regularly
- Use container registries and secret managers instead of inline secrets
```
